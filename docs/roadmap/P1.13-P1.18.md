This roadmap reflects the current develop baseline. P1.13–P1.15 already have implementation and changelog entries. Preserve those changes; do not reimplement them.

## Branch and release policy

- main: approved release baseline; never force-push or replace its tree.
- develop: integration branch for completed, CI-green development milestones.
- dev-infra: CI/CD, governance automation, and repository infrastructure.
- feature/*: short-lived milestone branches, deleted only after verified merge.
- Each milestone lands through a PR into develop.
- Synchronize main through a reviewed release/synchronization PR after reconciling its divergent commits. Do not merge development merely to remove an ahead/behind count.

## Completed milestones — retained baseline

### P1.13 — Ownership & Borrow Checker Hardening (0.0.14-d)
Implemented: conservative unknown-owner identity for CFG-merged references, safe parent suspension for joined child reborrows, and a regression for conflicting mutable borrows after a branch join. Remaining limitations: general interprocedural alias propagation, reference escapes, and closure-capture ownership.

### P1.14 — Type System Hardening (0.0.15-d)
Implemented: transactional generic unification, strict repeated generic parameter consistency, provisional Unknown refinement, effect-aware function type unification, invariant function parameter compatibility pending a formal variance model, and regression coverage. Deferred: full trait solver, recursive type inference, associated types, higher-kinded types, variance annotations, subtyping, and monomorphization.

### P1.15 — Effect System Foundation (0.0.16-d)
Implemented: explicit fn name! declarations and effectful function types, pure-to-effectful call rejection (E8001), effectful caller propagation, top-level host boundary, trait method effect signature checks (E4006), and EffectCheck checkpoint. Deferred: effect inference, effect polymorphism, algebraic effect handlers, capability-derived effects, and complete classification of built-in host operations.

## P1.16 — MIR Optimization Foundation (0.0.17-d)
- Add a pass manager with explicit pass identity, ordering, options, and per-pass verification.
- Add constant folding only where Seira overflow, division, and floating-point semantics are specified.
- Add dead-code elimination preserving observable effects, resource operations, and panic behavior.
- Add copy propagation and local simplification with SSA use-def validation.
- Preserve optimization-disabled mode for differential comparison.

Acceptance: MIR verifies before/after each pass; positive and negative regressions exist; optimized/unoptimized behavior agrees against an available execution oracle; passes are deterministic and independently configurable.

## P1.17 — Compiler Conformance & Differential Testing (0.0.18-d)
- Establish a versioned corpus for syntax, types, ownership, effects, diagnostics, and runtime outcomes.
- Add deterministic generated/property tests for lexer, parser, type checker, MIR verifier, and ownership analysis.
- Add bounded fuzzing; persist minimized failures as fixtures.
- Test source spans, package/workspace compilation, and CLI across supported platforms.
- Compare AST evaluator with MIR execution only if a MIR interpreter exists; never claim differential coverage against a nonexistent backend.
- Publish per-feature coverage and current test counts.

Acceptance: conformance suite runs in CI; fuzz regressions are reproducible; every semantic bug fix adds a fixture; test reporting lists exact counts and skips.

## P1.18 — Backend Readiness (0.0.19-d)
- Specify and validate target-independent MIR invariants at the backend boundary.
- Define target data layout, integer widths, alignment, aggregate layout, calling convention, symbol naming, and ABI versioning.
- Define runtime ABI for allocation, panic/unwind, cleanup, I/O, strings, collections, and closures.
- Define native/WASM capability matrix and explicit unsupported-feature diagnostics.
- Specify object format, linking, relocation, debug/source mapping, and artifact metadata.
- Add backend conformance fixtures and a minimal vertical slice only after code-generation technology and runtime ABI are approved.

Acceptance: backend contract is versioned/testable; invalid MIR is rejected before emission; target gaps are explicit; native/WASM remain NOT IMPLEMENTED until real emitters produce and execute artifacts.

## Definition of done

Every milestone requires implementation, regression tests, typecheck, full tests, security audit, CI matrix success, README and CHANGELOG synchronization, architecture status update, and a reviewable PR into develop. Documentation alone does not complete a milestone.
