# Seira Development Roadmap: P1.13–P1.18

| Field | Value |
|---|---|
| Baseline | 0.0.13-d |
| Target branch | `develop` |
| Working branch | `feature/p1.13-p1.18-hardening` |
| Status | Planned / implementation gated by acceptance criteria |
| Version sequence | 0.0.14-d through 0.0.19-d |
| Date | 2026-10-31 |

This roadmap is the authoritative forward plan for the next six Development milestones. A milestone is **not complete** merely because its design document or API surface exists. Completion requires implementation, regression tests, CI success, README and CHANGELOG updates, and a reviewable merge into `develop`.

## Release and branch policy

- `main`: release baseline only. Never force-push or replace its tree to make it look synchronized.
- `develop`: integration branch for completed, CI-green development milestones.
- `dev-infra`: CI, repository automation, release tooling, and infrastructure only.
- `feature/*`: short-lived milestone branches; delete only after merge is verified.
- Each milestone uses a PR into `develop`. Do not merge a divergent `develop` directly into `main` without reviewing the full diff and resolving conflicts.
- Keep `main` on the latest approved release. A deliberate release PR is the synchronization mechanism; branch divergence is not repaired by force-push.

## P1.13 — Ownership & Borrow Checker Hardening
**Target version: 0.0.14-d**

Scope:
1. Make CFG fixed-point analysis deterministic and monotone; document lattice and join semantics for owner, move, and loan states.
2. Harden loop-carried loans, branch merges, unreachable blocks, early returns, panic exits, and cleanup paths.
3. Define projection overlap over typed path segments rather than ambiguous string-only paths; retain conservative wildcard behavior for dynamic indices and keys.
4. Track partial moves and writes at projected places, or explicitly reject unsupported forms with stable diagnostics.
5. Define and test function-boundary borrow contracts. Until sound interprocedural propagation exists, reject unsupported escaping/aliasing cases conservatively.
6. Add regression fixtures for nested List/Map/Tuple/Struct paths, reborrow trees, and owner access after last use.

Acceptance:
- No unsound acceptance in the ownership regression corpus.
- Negative cases produce stable diagnostics with source locations.
- Positive disjoint-place cases remain accepted.
- Repeated test runs produce identical results.

## P1.14 — Type System Hardening
**Target version: 0.0.15-d**

Scope:
1. Audit generic substitution and unification for nested Option/Result/Map/Set/Tuple/Function/Reference types.
2. Make recursive type and alias-cycle detection explicit.
3. Validate trait constraints at generic call sites and implementation boundaries.
4. Specify variance/invariance rules for references and function types; do not infer variance accidentally.
5. Separate unresolved/unknown types from valid user-facing types and prevent Unknown from silently satisfying constraints.
6. Add a table-driven type conformance suite and stable diagnostic expectations.

Acceptance:
- Type equality, substitution, and unification are deterministic.
- Cyclic aliases and invalid generic constraints are rejected.
- Existing Seed and Development programs retain their semantics unless a documented bug fix is made.

## P1.15 — Effect System Foundation
**Target version: 0.0.16-d**

Scope:
1. Define canonical effect identities and effect-set representation.
2. Parse and resolve effect declarations and function effect annotations only after grammar/RFC approval.
3. Propagate effects through direct calls, higher-order calls, and generic substitutions.
4. Check declared effect bounds and pure-function restrictions.
5. Represent effect facts in HIR and preserve them through MIR lowering.
6. Distinguish language effects from host capabilities and runtime services.

Acceptance:
- Pure functions cannot perform undeclared effects.
- Effect propagation is deterministic across call graphs.
- Unsupported dynamic dispatch is conservatively checked.
- Tests cover direct calls, transitive calls, higher-order calls, and invalid annotations.

## P1.16 — MIR Optimization Foundation
**Target version: 0.0.17-d**

Scope:
1. Introduce an explicit pass manager with pass names, ordering, options, and verification boundaries.
2. Add constant folding only for operations with fully specified Seira overflow, division, and floating-point semantics.
3. Add dead-code elimination using side-effect/effect metadata; never remove observable effects or resource operations.
4. Add copy propagation and local simplification with SSA use-def validation.
5. Verify MIR before and after each optimization pass.
6. Keep an unoptimized mode for differential testing.

Acceptance:
- Every pass preserves MIR validity.
- Optimized and unoptimized execution agree for the supported execution path.
- Optimization is deterministic and can be disabled independently.

## P1.17 — Compiler Conformance & Differential Testing
**Target version: 0.0.18-d**

Scope:
1. Establish a versioned language conformance corpus with valid, invalid, runtime, and diagnostic fixtures.
2. Compare AST evaluator behavior with a MIR interpreter when that interpreter exists; do not claim differential coverage against a nonexistent backend.
3. Add property-based or deterministic generated tests for lexer, parser, type checker, and ownership invariants.
4. Add bounded fuzzing jobs and persist minimized regressions as fixtures.
5. Test deterministic diagnostics, source spans, package builds, and cross-platform CLI behavior.
6. Publish coverage by semantic feature rather than a stale aggregate test count.

Acceptance:
- CI runs the conformance corpus on supported OS/Node matrix.
- Fuzz failures are reproducible and minimized.
- Every fixed compiler bug adds a regression fixture.

## P1.18 — Backend Readiness
**Target version: 0.0.19-d**

Scope:
1. Specify target-independent MIR invariants and backend input validation.
2. Define target data layout, integer widths, alignment, aggregate layout, calling convention, symbol naming, and ABI versioning.
3. Define runtime ABI for allocation, panic/unwind, resources, I/O, strings, collections, and closures.
4. Define target capability matrix for native and wasm32; reject unsupported features explicitly.
5. Define object/linking model, debug/source mapping, relocation, and artifact metadata.
6. Add backend conformance fixtures and a minimal vertical-slice prototype only when the selected code-generation technology and runtime ABI are approved.

Acceptance:
- Backend contract is versioned and testable.
- Invalid MIR is rejected before emission.
- Target capability gaps are explicit diagnostics.
- Native/WASM code generation remains marked **not implemented** until a real emitter produces and executes artifacts.

## Documentation synchronization

The current `docs/architecture/*` set contains historical Seed specifications. Those documents remain useful as historical records, but their 0.0.10-s status labels must not be mistaken for current Development implementation status. The current-state document is the source of truth; historical documents must carry a visible historical-baseline notice.

## Definition of done for every milestone

- Implementation merged to its milestone branch.
- Unit, integration, conformance, and regression tests added.
- `npm run typecheck` and `npm test` pass.
- CI matrix and `npm audit --audit-level=high` pass.
- README status and examples match tested behavior.
- CHANGELOG records only changes actually implemented.
- Architecture docs and version metadata agree.
- PR reviewed; no force-push to `main`.
