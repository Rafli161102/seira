## P1.17 — Compiler Conformance & Deterministic Testing (0.0.18-d)
**Implementation:** feature/p1.17-conformance-testing; CI validation pending.

Implemented candidate:
- Development semantic conformance cases for generics, mutable-reference syntax, effect boundaries, type mismatch, and parser rejection.
- Repeated compilation comparison for diagnostic codes and primary source spans.
- Bounded deterministic lexer token fuzzing with fixed seed, EOF, monotonicity, and span-bound invariants.

True AST-vs-MIR differential execution is deferred because there is no MIR interpreter or executable native/WASM backend. This candidate must not claim differential testing beyond the reference compilation/diagnostic checks.

Acceptance: typecheck, full suite, npm audit, CI matrix, and branch governance all pass; every generated failure becomes a permanent regression.

## P1.18 — Backend Readiness Contract (0.0.19-d)
**Implementation:** feature/p1.18-backend-readiness; depends on P1.17 merge.

Implemented candidate:
- Versioned backend ABI contract types.
- Native/wasm32 target descriptor validation for triple, object format, pointer width, endianness, alignment, integer widths, and calling convention.
- Runtime ABI version and required symbol validation.
- Target capability validation.
- Backend request validation combining target contract checks and MIR verification.
- CompilerBackend rejects invalid MIR with E9003 before reporting E9001 for the unimplemented emitter.

Explicit limitations:
- No official native or wasm target triple, data layout, runtime ABI, calling convention, or code-generation technology has been selected.
- No LLVM/native or WASM emitter exists.
- Valid MIR still returns E9001; no object, executable, or wasm artifacts are generated.

Acceptance:
- Contract validation and MIR boundary tests pass.
- Invalid MIR is rejected before emission.
- Target profile fixtures are clearly illustrative until ABI review approves official profiles.
- Native/WASM remain NOT IMPLEMENTED until emitters produce artifacts and execute them in CI.

## Definition of done

Implementation, regression tests, typecheck, full suite, security audit, CI matrix, README/CHANGELOG/version synchronization, architecture updates, and reviewable PR into develop are required. A specification alone does not complete a milestone.
