## Branch and release policy

- main: approved release baseline.
- develop: compiler/language integration.
- dev-infra: CI/CD and repository infrastructure.
- feature/*, fix/*, docs/*: temporary branches targeting develop.
- infra/*: temporary infrastructure branches targeting dev-infra.
- Permanent branch histories must never be rewritten to manufacture synchronization.
- Merged temporary branches are deleted by the Branch Governance workflow after ancestry verification. Existing historical branches may be cleaned up through its guarded manual workflow.
- Branch protection/rulesets still require repository-maintainer configuration.

## Completed milestones

### P1.13 — Ownership & Borrow Checker Hardening (0.0.14-d)
Merged. CFG joins no longer select one owner when a reference may originate from different roots. A conservative unknown-owner identity prevents missed alias conflicts, and unknown parent reborrows retain conservative parent suspension. Regression coverage includes conflicting mutable borrows after a branch join.

Deferred: general interprocedural alias propagation, reference escapes, closure-capture ownership, and full partial-move semantics.

### P1.14 — Type System Hardening (0.0.15-d)
Merged. Generic unification is transactional; repeated generic variables must agree structurally; Unknown inputs can be refined; function unification includes effect markers; function parameter compatibility is invariant pending formal variance rules.

Deferred: full trait solver, recursive inference, associated types, higher-kinded types, subtyping, variance annotations, and monomorphization.

### P1.15 — Effect System Foundation (0.0.16-d)
Merged. Explicit effectful function declarations/types, pure-to-effectful call rejection (E8001), effectful caller propagation, top-level host boundary, trait effect signature checks (E4006), and EffectCheck checkpoint.

Deferred: effect inference, effect polymorphism, algebraic handlers, capability-derived effects, and complete host-operation classification.

## P1.16 — MIR Optimization Foundation (0.0.17-d)
**Implementation:** feature branch; CI validation pending.

Implemented:
- Named pass manager with deterministic pass order.
- Constant folding and constant-branch simplification.
- Unreachable basic-block elimination.
- Dead pure-operation elimination.
- Preservation of calls, resource operations, dereferences, potentially trapping division, and unknown operations.
- Resource event position remapping after dead operations are removed.
- MIR verifier callback after every pass candidate; invalid candidates are not committed and produce E4005 in the compiler driver.
- optLevel 0 preserves input MIR; optLevel 1 enables the conservative pass set; levels 2/3 currently reuse O1.

Regression coverage includes arithmetic folding, branch pruning, side-effect/trap preservation, driver integration, optLevel 0 identity, resource event remapping, and pass-verifier rollback.

Deferred: copy propagation, loop optimization, global value numbering, inlining, and target-specific lowering. Do not call the optimizer production-grade.

Acceptance: TypeScript typecheck, full tests, npm audit, CI matrix, and branch governance must pass before merge.

## P1.17 — Compiler Conformance & Differential Testing (0.0.18-d)
Planned scope:
1. Build a versioned conformance corpus for valid/invalid syntax, types, ownership, effects, diagnostics, and runtime outcomes.
2. Add deterministic generated/property tests for lexer, parser, type checker, MIR verifier, and ownership analysis.
3. Add bounded fuzzing and persist minimized failures as fixtures.
4. Verify source spans, package/workspace compilation, CLI behavior, and cross-platform execution.
5. Use AST evaluator comparisons as a reference oracle for available semantics. Do not claim AST-vs-MIR differential execution until a MIR interpreter exists.
6. Publish exact test counts and feature-level coverage, not stale Seed-era totals.

Acceptance: CI executes the corpus on the supported OS/Node matrix; fuzz regressions are reproducible; each fixed semantic bug adds a permanent fixture.

## P1.18 — Backend Readiness (0.0.19-d)
Planned scope:
1. Specify target-independent MIR invariants and backend input validation.
2. Define target data layout, integer widths, alignment, aggregate layout, calling convention, symbol naming, and ABI versioning.
3. Define runtime ABI for allocation, panic/unwind, resource cleanup, I/O, strings, collections, and closures.
4. Define native/WASM target capability matrix and explicit unsupported-feature diagnostics.
5. Specify object format, linking, relocation, debug/source mapping, and artifact metadata.
6. Add backend conformance fixtures and a vertical-slice prototype only after code-generation technology and runtime ABI are approved.

Acceptance: backend contract is versioned and testable; invalid MIR is rejected before emission; target gaps are explicit. Native/WASM remain NOT IMPLEMENTED until real emitters produce artifacts and execute them in CI.

## Definition of done

A milestone is complete only after implementation, regression tests, typecheck, full tests, security audit, CI matrix success, README/CHANGELOG/version synchronization, architecture updates, and a reviewable PR into develop.
