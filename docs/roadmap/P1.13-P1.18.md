## Completed milestones

- **P1.13 / 0.0.14-d — Ownership & Borrow Checker Hardening:** conservative unknown-owner/parent identities for CFG-merged loans and branch-join conflict regression.
- **P1.14 / 0.0.15-d — Type System Hardening:** transactional generic unification, repeated generic variable consistency, Unknown refinement, effect-aware function unification, and invariant function parameters.
- **P1.15 / 0.0.16-d — Effect System Foundation:** explicit effectful declarations/types, E8001 pure-call boundary, effectful caller propagation, trait effect signature checks, and EffectCheck checkpoint.
- **P1.16 / 0.0.17-d — MIR Optimization Foundation:** named verifier-gated pass manager, constant folding/branch simplification, unreachable block removal, dead pure-op elimination, and resource position remapping.
- **P1.17 / 0.0.18-d — Compiler Conformance & Deterministic Testing:** semantic conformance matrix, stable diagnostic comparison, and deterministic bounded lexer fuzzing. True AST-vs-MIR differential execution remains deferred because no MIR interpreter exists.
- **P1.18 / 0.0.19-d — Backend Readiness Contract:** versioned backend/runtime ABI contract, native/wasm32 descriptor validation, target layout checks, runtime ABI symbol checks, backend request validation, and E9003 invalid-MIR rejection before the still-unimplemented emitter boundary.

## Explicit project limitations

- Native LLVM and WebAssembly code generation are not implemented.
- Valid MIR still returns E9001 at the backend boundary.
- No native executable, object file, or wasm artifact is produced or executed.
- Test target triples and ABI symbols are illustrative, not approved production profiles.
- The runtime remains the TypeScript tree-walking evaluator.
- Ownership still lacks reference escapes, general interprocedural alias propagation, and closure-capture ownership.
- Effects remain an initial explicit call-boundary system, not full algebraic effects.

## Definition of done

P1.13–P1.18 are merged to develop, with main synchronized to 0.0.19-d through PR #20. Future milestones must retain the same standard: implementation, regression tests, typecheck, full suite, security audit, CI matrix, README/CHANGELOG/version synchronization, architecture updates, and a reviewable PR.
