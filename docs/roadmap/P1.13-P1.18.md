## P1.17 — Compiler Conformance & Deterministic Testing (0.0.18-d)
**Implementation:** feature branch; CI validation pending.

Implemented candidate:
1. Development semantic conformance matrix for generic inference, mutable-reference syntax, effect-call rules, invalid type programs, and parser rejection.
2. Repeated compilation comparison for stable diagnostic codes and source spans.
3. Bounded deterministic lexer fuzzing with a fixed LCG seed, generated token fragments, EOF checks, monotonic spans, and source-bound checks.

Explicit boundary:
- This is deterministic generated testing, not an unbounded fuzzing service.
- True AST-vs-MIR differential execution is deferred because the repository has no MIR interpreter or executable native/WASM backend.
- Differential comparison must not be advertised until both independent execution paths exist.

Acceptance:
- Typecheck, full suite, npm audit, and CI matrix pass.
- Every failure found by generated tests becomes a fixed regression.
- The conformance matrix reports stable expected outcomes and diagnostic codes.

## P1.18 — Backend Readiness (0.0.19-d)
Planned scope:
1. Specify target-independent MIR invariants and backend input validation.
2. Define target data layout, integer widths, alignment, aggregate layout, calling convention, symbol naming, and ABI versioning.
3. Define runtime ABI for allocation, panic/unwind, resource cleanup, I/O, strings, collections, and closures.
4. Define native/WASM target capability matrix and explicit unsupported-feature diagnostics.
5. Specify object format, linking, relocation, debug/source mapping, and artifact metadata.
6. Add backend conformance fixtures and a vertical-slice prototype only after code-generation technology and runtime ABI are approved.

Acceptance:
- Backend contract is versioned and testable.
- Invalid MIR is rejected before emission.
- Target capability gaps are explicit diagnostics.
- Native/WASM remain NOT IMPLEMENTED until real emitters produce artifacts and execute them in CI.

## Definition of done

A milestone is complete only after implementation, regression tests, typecheck, full tests, security audit, CI matrix success, README/CHANGELOG/version synchronization, architecture updates, and a reviewable PR into develop.
