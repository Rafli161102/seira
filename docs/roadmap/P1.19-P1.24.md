# Seira Development Roadmap: P1.19–P1.24

| Field | Value |
|---|---|
| Baseline entering this phase | 0.0.19-d |
| P1.19 target release | 0.0.20-d |
| Audit date | 2026-10-31 |

## P1.19 — MIR Interpreter Foundation

**Goal:** Execute a verified, explicitly bounded subset of scalar MIR so compiler tests can compare the AST evaluator with MIR execution.

**Scope:** SSA value storage, block-parameter edge transfer, direct in-module calls, scalar constants/operators, strict boolean branches, step/call-depth limits, fail-closed diagnostics, and differential tests for return values.

**Not included:** Host I/O, resource operations, references, aggregate values, iterators, closures, indirect calls, native or WASM emission.

## P1.20 — Differential Conformance Expansion

Add deterministic generated programs and broaden AST-vs-MIR parity for the supported language subset. Introduce a shared test-value normalization layer and compare diagnostics for invalid MIR/runtime cases. Do not claim coverage for unsupported runtime operations.

## P1.21 — MIR Runtime Semantics

Define and implement MIR semantics for aggregate values, place projections, references, mutable stores, borrow lifecycle, and resource acquire/release cleanup. Reconcile runtime invariants with the static ownership analysis.

## P1.22 — Runtime Host ABI

Specify typed host-call descriptors, capability/effect mapping, deterministic output capture, panic/error transport, and explicit builtin/external call registration. Avoid implicit host calls from the MIR interpreter.

## P1.23 — Native Backend Vertical Slice

Choose and document one supported native target and ABI profile. Implement a minimal, verifiable executable/object emission path for the P1.21/P1.22-supported MIR subset, including a runnable smoke test. Only claim the exact target and operations actually emitted.

## P1.24 — WebAssembly Backend Vertical Slice

Choose a concrete wasm32 ABI/runtime profile and implement a minimal validated module emission and execution path. Add artifact-level conformance tests and document runtime imports/exports.

## Quality gates for every milestone

- Preserve ownership, type, effect, and MIR verifier invariants.
- Add focused regression tests before broadening implementation claims.
- Run typecheck, complete test suite, npm audit, and all supported CI matrix jobs.
- Update README, CHANGELOG, package/lock/manifest/CLI versions, and architecture/roadmap docs together.
- Develop on temporary feature branches and merge through reviewed pull requests.
- Keep main synchronized only after develop validation; native/WASM implementation status must reflect real artifact generation.
